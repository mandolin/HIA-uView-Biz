# Architecture overview / 架构概览

HIA-uView-Biz is a configurable, capability-composed UniApp business framework. Its first target is mini-program development, while its public contracts keep backend, identity, industry model, and presentation channel replaceable.

HIA-uView-Biz 是可配置、按能力组合的 UniApp 业务框架。其首要目标是小程序开发，同时其公开契约保持后端、身份、行业模型和呈现渠道可替换。

| Area / 区域 | Responsibility / 主责 | Boundary / 边界 |
| --- | --- | --- |
| `packages/core` | Composition rules, manifest validation, declared ports, and validation hooks / 组合规则、manifest 校验、已声明 port 与验证挂钩 | Does not own domain records, routes, transport, or credentials / 不拥有领域记录、路由、传输或凭据 |
| `packages/app-shell` | In-memory screen-state projection, action gate, mock capability gate, canonical failure presentation input, and retry command retention / 内存 screen-state 投影、action gate、mock capability gate、规范化 failure 呈现输入和 retry command 保留 | No Vue, UniApp, URL/router, platform navigation, storage, real identity, transport, or UI registration / 没有 Vue、UniApp、URL/router、平台导航、storage、真实身份、传输或 UI 注册 |
| `packages/adapter-runtime` | Explicit read-adapter declaration, injected exchange lifecycle, canonical-outcome boundary, redaction, and optional bounded memory cache / 显式 read-adapter 声明、注入式 exchange lifecycle、canonical-outcome 边界、脱敏与可选受限内存缓存 | No network client, backend SDK, environment, credential, storage, persistent cache, write operation, UI, or route / 没有网络 client、backend SDK、环境、credential、storage、持久缓存、写操作、UI 或 route |
| `packages/capability-runtime` | Explicit multi-unit install/enable/disable/uninstall state, dependency/conflict checks, unique ownership, invocation routing, and redacted snapshots / 显式多单元安装/启用/停用/卸载状态、依赖/冲突检查、唯一主责、调用路由与脱敏 snapshot | Process-local only; no package discovery/installation, hooks, automatic dependency activation, persistence, remote code, UI, or backend / 仅进程内；没有包发现/安装、hook、自动依赖启用、持久化、远程代码、UI 或后端 |
| `modules` | Capability-oriented business ownership and schemas / 面向能力的业务主责与 schema | Separates business semantics from package delivery / 与包交付事实分离 |
| `extensions` | Explicit adapters and other documented extension packages; currently includes one neutral injected-wire fixture / 显式 adapter 与其他有文档的扩展包；当前包含一个中性注入式 wire fixture | No hidden coupling to application internals, real backend discovery, or implicit fallback / 不得隐式耦合应用内部实现、发现真实后端或隐式 fallback |
| `apps/example-catalog-query-detail-mp-weixin` | Versioned declarative profile, explicit mock/wire source, app-owned lifecycle-to-shell bridge, registered presentation projection, and controlled UniApp Vue 3 compiler fixture / 带版本声明式 profile、显式 mock/wire source、app-owned lifecycle-to-shell bridge、已登记呈现投影与受控 UniApp Vue 3 compiler fixture | Representative `mp-weixin` only; no dev server, source fallback, router, real backend adapter, real identity, write flow, arbitrary component/script, or release claim / 仅代表性 `mp-weixin`；没有 dev server、source 回退、router、真实后端 adapter、真实身份、写流程、任意组件/脚本或发布声明 |
| HIA-uView | Presentational UI input to the controlled fixture / 受控 fixture 的呈现 UI 输入 | Uses a reviewed local source guard, one-use local link, explicit SFC imports, and explicit style; no external `file:` package dependency / 使用已复审的本地 source guard、一次性本地 link、显式 SFC 导入和显式样式；没有外部 `file:` package dependency |

The detailed decision is [ADR-0001: Business composition and contract boundaries](adr/ADR-0001-biz-composition-and-contract-boundaries.md). It defines the module/implementation manifest split, canonical adapter outcomes, profile and channel projection, and declarative dynamic-presentation boundary.

详细决定见 [ADR-0001：业务组合与契约边界](adr/ADR-0001-biz-composition-and-contract-boundaries.md)。该 ADR 定义模块/实现包 manifest 分离、adapter 规范化结果、profile 与渠道投影，以及声明式动态呈现边界。

The current runtime implements the core's explicit manifest/profile/port composition boundary, deterministic neutral mock, pure application shell, a backend-agnostic adapter lifecycle, and an explicit process-local capability lifecycle. The capability runtime validates units through core, keeps install separate from enablement, enforces dependency-first activation and symmetric conflicts, protects active dependencies, routes only enabled modules, and removes disabled units without hooks. The neutral adapter fixture uses only injected local query/detail exchanges and a mock session; it proves canonical conversion, failure redaction, explicit implementation replacement, optional process-local success caching, and a full capability lifecycle without a real transport. The representative app now validates a versioned JSON profile before source construction, explicitly selects either the wire fixture or mandatory mock without fallback, installs and enables the selected unit, bridges only enabled invocation into app shell, and lets registered block IDs reveal only compiled template branches. Its Node acceptance exercises query, detail, back, empty/failure, detached snapshots, and bounded adapter observation. The controlled compiler then compiles the explicit-SFC HIA-uView projection for `mp-weixin` after verifying an operator-provided local UI source. The stack still does not implement package discovery/installation, lifecycle scripts, automatic dependency activation, persistence, a real HTTP/Directus adapter, real identity integration, industry package, write flow, URL/router, dynamic executable configuration, or published UI dependency.

当前运行时实现了 core 的显式 manifest/profile/port 组合边界、确定性中性 mock、纯应用 shell、backend-agnostic adapter lifecycle，以及显式进程内 capability lifecycle。capability runtime 通过 core 校验单元，分离安装与启用，强制依赖优先激活与双向冲突，保护活动依赖，只路由已启用模块，并在无 hook 的情况下移除已停用单元。中性 adapter fixture 只使用注入式本地 query/detail exchange 与 mock session；它在没有真实 transport 的情况下证明 canonical conversion、failure 脱敏、显式 implementation 替换、可选进程内成功缓存和完整 capability lifecycle。代表性 app 现在会在构造 source 前校验带版本 JSON profile，明确选择 wire fixture 或必备 mock 且不回退，安装并启用所选单元，只把已启用调用桥接给 app shell，并使已登记区块 ID 只能显示已编译 template 分支。其 Node 验收执行 query、detail、返回、empty/failure、隔离 snapshot 与受限 adapter observation。随后，受控 compiler 在校验操作者提供的本地 UI source 后，为 `mp-weixin` 编译显式 SFC 导入的 HIA-uView 投影。该 stack 仍不实现包发现/安装、生命周期脚本、自动依赖启用、持久化、真实 HTTP/Directus adapter、真实身份集成、行业包、写流程、URL/router、动态可执行配置或已发布 UI dependency。
